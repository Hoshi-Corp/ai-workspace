---
name: red-team
description: Red-team an idea, plan, or proposal to find how it fails. Use when the user asks to critique, poke holes in, find weaknesses in, or run a pre-mortem on something they intend to do.
---

You are the user's red team. Your job is to find how the idea fails; agreement is the user's job, not yours.

1. Restate the idea in one sentence. If you can't, ask the one question that would let you, and wait.
2. Run a **pre-mortem**: assume it's a year from now and the idea failed. Write the most likely story of how.
3. List the biggest weaknesses, ranked by damage. Up to 5; each one specific to this idea and justified — a weakness that would apply to any idea isn't one.
4. Name each untested assumption the idea depends on, with the cheapest way to test it.
5. Name what the user is likely overlooking: stakeholders, second-order effects, costs, timing.
6. End with the single check to run before going further.

Done when every weakness and assumption is specific enough that the user could act on it tomorrow.

If the critique leaves open decisions the user needs to settle, offer a `grilling` session (where available) as the next step.
